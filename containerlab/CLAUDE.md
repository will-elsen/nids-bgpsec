# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A BGPsec/RPKI teaching lab: six BGP autonomous systems in Containerlab that students attack and defend through four curriculum states. **The deliverable is `lab/bgpsec-lab.ipynb`; everything else exists to make that notebook work.** `REFERENCE.md` at the repo root is the complete walkthrough — read it before changing, debugging, or judging anything here. `lab/phase3/PHASE3.md`, `lab/phase4/PHASE4.md` and `lab/PHASE5.md` record measured QuaggaSRx/SRx-server/containerlab behaviours; read those before concluding something is a bug.

## Commands

All from `lab/`:

```bash
python3 tools/smoke_test.py           # drives all four parts with the notebook's assertions (~10 min)
python3 tools/smoke_test.py c         # one part only — the "single test" granularity
python3 tools/run_notebook.py bgpsec-lab.ipynb   # execute the notebook like a kernel (~15 min)

python3 tools/build_notebook.py       # regenerate BOTH notebooks from source
python3 tools/gen_configs.py phase4   # regenerate all 24 router configs from the topology table
bash tools/build_vault.sh             # (re)build phase4/keys from the tracked private keys; --force to redo

./reset.sh [a|b|c|d]                  # clean state without redeploy; --hard destroys and redeploys
./build-images.sh                     # rebuild the :upstream and :local images from source
docker load < dist/bgpsec-lab-images.tar.gz   # load the prebuilt image bundle

containerlab deploy  -t phase4/bgpsec-p4.clab.yml
containerlab destroy -t phase4/bgpsec-p4.clab.yml --cleanup
```

Driving the lab from Python: `import labkit as lab` — `lab.status()` is the first move when debugging; `lab.deploy()`, `lab.set_part("a".."d")`, `lab.attack("hijack"|"forge"|"stop")`, `lab.show(node)`. §12 of REFERENCE.md is the full API.

Run the smoke test after touching `gen_configs.py`, `labkit.py`, or anything in `overlay/`.

## Generated files — edit the source, not the output

- **Both notebooks** (`bgpsec-lab.ipynb`, `bgpsec-lab-instructor.ipynb`) are generated by `tools/build_notebook.py`. Editing the `.ipynb` directly makes the student and instructor copies drift.
- **All router configs** in `phase4/configs/{a,b,c,d}/` are generated by `tools/gen_configs.py` from one topology table. `configs/active/` is whatever `set_part` last copied in.
- **The key vault** (`phase4/keys/`) is built by `tools/build_vault.sh` from the tracked private keys — the vendored testbed's four plus `router_keys/` — and `labkit.deploy()` runs it. It is gitignored on purpose: a deploy rewrites its certificates and chowns the keys to root. Never hand-edit it; rotate a key in `router_keys/` and rebuild instead.
- **`bgpsec-testbed/`** is a deliberately unmodified vendored clone of SIDN's testbed. Never edit it; lab-owned overrides live in `lab/configs/` and are bind-mounted over the top, so upstream stays diffable.
- **`phase4/clab-bgpsec-p4/`** is containerlab's runtime directory, recreated on every deploy — disposable.

## Architecture

Topology: `AS64602 (origin) — AS64601 — AS64603 — AS64604 (victim) — AS64605 (observer)`, with attacker AS64666 peered to AS64604. Routers are QuaggaSRx except the observer (GoBGP-SRx). An RPKI plane rides the management network only: Krill (CA) → rsyncd (publication point) → Routinator (validator) → SRx-server (validation engine). Inter-AS links are dedicated veth pairs so BGPsec signature growth can be captured hop by hop — that is the whole reason this is Containerlab and not the upstream docker-compose bridge.

Two independent validation paths, which matters for debugging:
- **QuaggaSRx routers** delegate everything (RTR and signature checks) to `srx_server` over the proxy protocol on :17900. If `srx_server` is unhappy, all five lose both origin and path validation.
- **GoBGP-SRx (AS64605)** talks RTR directly to Routinator for origin validation and verifies signatures locally against the shared key vault (`phase4/keys/`). It never touches `srx_server`.

Four curriculum states, switched in place by `set_part`: **a** nothing on, **b** ROV drops invalids, **c** ROV + BGPsec drop invalids, **d** partial deployment — AS64602 speaks plain BGP and invalids are de-preferred, not dropped (`PARTS` table in `gen_configs.py`; note some docstrings there stale-ly say AS64603). RPKI state (ROAs, certificates) survives part switches by design — the curriculum narrative depends on it.

## Hard-won constraints — do not rediscover these

- **Never `docker restart` a lab node.** Containerlab veths do not survive container recreation: the node comes back with only `eth0`, everything shows `Up`, and nothing reports an error. The `:local` images run a supervisor as PID 1 precisely so daemons restart in place (`pkill -x bgpd`, or `lab.restart_daemon(node)`). Recovery from recreation is destroy `--cleanup` + deploy.
- **Krill is pinned to v0.14.5** — 0.15 removed the krillc flags the testbed's `sign_csr.sh` uses; on `latest` the deploy hangs with an empty trust anchor.
- **One-shot containers (`krillc`, `tal_share`) need `restart-policy: "no"`** or `wait-for: {stage: exit}` never fires and the deploy hangs.
- **BGPsec cannot be toggled on a live QuaggaSRx session** — it only takes effect at daemon start; hence part switches restart daemons. `srx_server` must restart first (stale proxy-ID client table otherwise blocks router reconnects: every session Established, no routes anywhere, no log names the cause).
- **A signing QuaggaSRx signs on every session** regardless of per-neighbour settings, which is why part d's gap is at the origin. An unsigned route on a BGPsec session scores Invalid, not unknown.
- **`phase4/state/`** (rsync_repo, rsync_ta) is written by containers running as root — clear it through a container, never with `sudo` on the host.
- **10.0.0.1 is the mgmt bridge's own gateway** — never assign it to a node.
- Nothing in the lab needs `sudo`; keep it that way (captures run inside containers via `docker exec`).
